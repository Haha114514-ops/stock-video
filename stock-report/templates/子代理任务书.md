# 子代理任务书（stock-report）

> 主控把对应一节的 `<…>` 填好，整节作为子代理的任务说明发出去。子代理从零开始，只知道这里写的东西，所以路径写全。
> `<video>` = stock-video 目录，`<report>` = stock-report 目录。
> **模型档位**照 stock-video 的任务书开头：材料员、排版员用**执行档**（当前平台较便宜、较快的模型），主控、口径审员用**判断档**（最强的模型）。各平台怎么指定、怎么"继续同一个子代理"，看 `<video>/templates/子代理任务书.md` 开头的对照表。

---

## 一、材料员

**直接用 `<video>/templates/子代理任务书.md` 第一节，一字不改**，只把开头"你在为一期个股视频读材料"换成"你在为一份个股图文报告读材料"。交回同样的 `<工程>/材料摘录.md` + 300 字以内的消息。

同一家公司已经做过视频（工程里有 `材料摘录.md`、`facts.json`）时不再起材料员：主控只补截止日之后的新材料（新一期季报、公告）。

---

## 二、口径审员（报告稿交排版员前；之后改过的段落再交回来）

你是这份个股图文报告的口径审员。只读这五样：`<工程>/data/`、`<工程>/facts.json`、`<工程>/报告稿.md`、`<工程>/report_check.txt`（脚本已查过的机械项和"正文数字 ↔ facts 说法"对照表，从对照表开始看）、`<工程>/材料摘录.md` 的第 0 节（命门线索）。不要读 故事.md。
**怎么读**：facts 用 `python <video>/scripts/facts_peek.py <工程> [键前缀…]` 看，不整份读、不打印序列；`data/` 只按需查（表格 grep 要的那几行；报告先看 `reports/<标题>_目录索引.md` 和切好的段）。报告稿里的 `{{键|规格}}` 就是 facts 里那个键的值，规格见 `<report>/scripts/rlib.py` 的 `fmt`。

逐条回答下面六问，每条写：哪一章哪一段（引前十个字）→ 问题 → 依据（facts 键或 data 里的文件 / 行）→ 建议改成什么。没问题写"无"。
1. 正文里每个数的说法（时间窗、对象、口径），和 facts.json 的 `labels` / data/ 一致吗？
2. 公告类事实对照 `quotes` 原文：有没有漏掉条件、例外，或改写成原文没有的意思？
3. 推算：前提写全了吗（已扣什么、没算什么）？截止日之后已发生的支出扣了吗？图角注（charts.py 的 note=）和正文是同一个前提吗？
4. 有没有说过头：单一归因、把"市场在定价什么"写成事实、像目标价或买卖建议、核心论据未经审计却没说？"推测"框外的句子有没有下了推测性的结论？
5. 结论和文中推算矛盾吗（把文中算出已在发生的事写成"如果发生才不便宜"）？摘要和结尾说的是同一个结论吗？
6. 命门漏了吗：`材料摘录.md` 第 0 节的每条线索，报告里交代了没有？没交代的，有没有写不讲的理由？一个懂这行的人读完，最可能问"怎么没讲 X"的 X 是什么？

另外核一项画法：文件头"三表总览"指的三张图（看 `<工程>/charts.py` 里同名函数），是不是把整张表摆出来了——资产负债表同一时点"有什么""钱是谁的"两边都有，利润表从收入切到归母，现金流量表经营 / 投资 / 筹资都在。只画了故事要用的那一项不算总览，在逐条结果最前面单列一条"三表总览"。

写的人想写得有冲击力是正常的，你的活是对着数据把他拉住。只核口径，不评价好不好看。
**回给主控的消息**：逐条结果（不复述没问题的段落）。复核轮只核主控发来的改动段落，前五问。

## 三、排版员（报告稿过了 report_check 和口径审片后）

你负责把定稿的报告稿做成 PDF。工程 `<工程路径>`，stock-report 目录 `<report>`。

**开工只读这些**：
- `<工程>/报告稿.md`（图名、每段在讲哪一块就是图的规格）
- `<工程>/facts.json`：用 `python <video>/scripts/facts_peek.py <工程> [键前缀…]` 看键名、值和说法，不整份读
- `<report>/SKILL.md` 第 4、5 步和"已知坑"
- `<report>/scripts/rcharts.py` 文件头和各函数的 docstring（`grep -n '^def \|"""' rcharts.py` 先看目录，用到哪个读哪个）
- `<report>/templates/charts_skeleton.py`

**做**：复制骨架建 `<工程>/charts.py`，报告稿里每个 `[[图 名字]]` 一个同名函数；`python <report>/scripts/build_report.py <工程>` 出 PDF；`pdftoppm -r 50 -png` 或浏览器打开 HTML 看每页；按下面的规矩改到没问题。最后跑一遍 `python <report>/scripts/report_check.py <工程>`。

**规矩**：
- 正文一个字都不改。觉得要改字（图和文对不上、段落太长），停下来把段落和理由报给主控。
- 数字只从 FX 取，不在 charts.py 里手写数；图上的数和正文写的数是同一个键。
- 每张图的 focus= 对准讲它的那段在讲的那一块；整段都在讲全貌就不设 focus。
- 每张图的 note= 写口径：时间、单位、"推算"及前提、"未经审计"、"示意"；资产负债表写"同一时点"。
- 颜色有含义：涨红跌绿；红绿表示对利润好坏时要有图例（waterfall / cash_bridge 自带）。坐标从 0 起（比率、价格、对数轴例外，note 里写明）。
- 一页里图不被切开（已设 break-inside: avoid）；某页只剩一两行就让图缩一点（函数的 w= / h=）。
- charts.py 第一次写完以后只做局部修改；命令输出只看最后几行；每轮最多看一次页面图片。

**回给主控的消息**不超过 300 字：PDF 路径和页数；每张图 focus 了什么；和报告稿不一样的地方及原因；还没解决的问题。
