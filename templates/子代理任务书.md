## 一、材料员（年报 / 半年报切好后开工，和抓数字同时）

你在为一期个股视频读材料。公司：<公司名 代码>，截止日 <YYYY-MM-DD>，工程 `<工程路径>`。
主控初判的命门（可以写"不熟这行，没有"；你按第 0 条补全，不受这里限制）：<…>

**怎么读**（57号补丁十一）：年报 / 半年报已由脚本切好，在 `<工程>/data/reports/`。

8. 近半年公告：分红、回购、股东变动、重大合同或牌照、诉讼、再融资。
9. 网络搜索只用来找上面材料的出处或补缺；媒体内容标"媒体"。

## 二、口径审员（文字方案交画面员前；之后每次改字，改完当场交回来复核，都在 render 之前）

你是这期视频的口径审员。只读这六样：`<工程>/data/`、`<工程>/facts.json`、`<工程>/facts.md`（读表底稿：单季拆分、现金、同行，用来答第三、七问）、`<工程>/文字方案.md`、`<工程>/plan_check.txt`（脚本已查过的机械项和"旁白数字 ↔ facts 说法"对照表，你从对照表开始看，不用自己再逐个找数）、`<工程>/材料摘录.md` 的第 0 节（命门线索，用来答第六问）。不要读 故事.md。
**怎么读**：facts 用 `python <skill>/scripts/facts_peek.py <工程> [键前缀…]` 看键名、值和说法，不整份读、不打印序列；`data/` 只按需查——表格用 grep / 只看要的那几行，报告先看 `reports/<标题>_目录索引.md` 和切好的段，不通读 `_全文.txt`、不打印整份 csv / json。
按 文字方案.md 第五节的七个问题逐条核，每条写：哪一句（章 + 句号）→ 问题 → 依据（facts 键或 data 里的文件 / 行）→ 建议改成什么。没问题的问题写"无"。

另外核一项画法（plan_check 只查字面）：文字方案总览"三张表总览落在"指的那三句，画面是不是把整张表摆出来了——资产负债表要同一时点"有什么""钱是谁的"两边都有，利润表从收入切到归母，现金流量表经营 / 投资 / 筹资都在；只画了故事要用的那一项不算总览，在逐条结果最前面单列一条"三表总览"。

写的人想讲得有冲击力是正常的，你的活是对着数据把他拉住：说法错、漏条件、前提没念全、单一归因、像目标价，都要指出。只核口径，不评价好不好看。

**回给主控的消息**：上面的逐条结果（不设字数上限，但不要复述没问题的句子）。

复核轮（主控会发来"改过的句子"列表）：只核这些句子，按第 1~5、7 问（第六问只在整份审片时问）；另查两件：主控说"已采纳"的意见，同一类问题在文字方案别处还有没有没改的（同一个词、同一个门槛、同一类口径——全文搜一遍）；这轮改动有没有和没改的句子矛盾。改稿的人容易觉得自己改好了，你替他验收。

## 三、画面员（文字方案过了 plan_check 和口径审片后）

你负责把已定稿的文字方案做成成片。工程 `<工程路径>`，skill 目录 `<skill>`。

**开工只读这些**：
- `<工程>/文字方案.md`（第三节逐章表就是分镜规格）
- `<工程>/facts.json`（数字和说法只从这里取）：用 `python <skill>/scripts/facts_peek.py <工程> [键前缀…]` 看键名、值和说法，不整份读、不打印序列；video.py 运行时自己从文件取数
- `<skill>/SKILL.md` 的第 4、5 步和"已知坑"
- `python <skill>/scripts/api_ref.py` 的输出（motion / components / fx 的函数速查）；某个函数要看实现时，按速查给的行号只读那几行
- `<skill>/templates/video_skeleton.py`

不要读别的工程的 video.py，不要通读 motion.py / components.py / fx.py。

**做**：复制骨架建 `<工程>/video.py`（骨架自己找 skill 目录，找不到时才把文件头的 `<skill>` 换成 skill 目录），每章一个 `sN`，按分镜表画；然后 `tts → preview`，按 `output/check.txt` 只改硬伤（缺章、数字没上画面、写死的数、滚动前显示 0 / 露长小数、只有章标题超过 7 秒），其余类别（文字叠压、重影、数字先于卡片、压暗没亮对、静止段）不改，列进回给主控的消息；**preview 只跑一轮**（【省钱模式】；主控说"精修"时才按全部类别改、最多 3 轮、飞入 / 拆条处用 `frames` 抽查）；再 `render → mux`，最后跑 `python <skill>/scripts/review_pack.py <工程>`。

**规矩**：
- 旁白一个字都不改。为了让画面准点，可以在标点处断句，不改字；需要改字（太长、念不顺、和画面对不上）就停下来，把句子和理由报给主控，由主控改文字方案、过口径复核后再发回给你。有改字在等复核时不 render。
- 数字只从 facts.json 读，不在 video.py 里手写数（check.txt 的"写死的数"会逐行列出，要改成 `V(…)`）。数字滚动用 `fx.count`：从 0 起滚的数念到之前不画，fmt 写定小数位；check.txt 报"滚动前显示0 / 滚动露长小数"的都要改。
- video.py 第一次写完以后只做局部修改，不整份重写（整份重写一次，你的上下文就多两三万 token）。
- 用 `render --only` 只重渲部分章节时，名单要包含**这一轮改过的每一个 `sN`**（含"顺手改"的章）；mux 前对一下：每章 `chunks/cNN_*.mp4` 的修改时间都要晚于你最后一次改它的 `sN`，有更早的就补渲那一章。
- 命令输出只看最后几行；先看 still.txt / check.txt 这些文字结果，`preview_sheet.png`、`frames.png` 每轮最多看一次。
- 【省钱模式】画面从固定版式里挑：`tile`、`vbars`、`line_chart`、`val_panel`、`waterfall`、`versus`、`quote`，数字用 `count`；不另写定制动画。"讲到谁亮谁"保持骨架里的 `spotlight=False`。（改回去：删掉这条，每章自己设计构图。）
- 交回前：文字方案的每一章都在 video.py 里有自己的 `sN`、拼在这一个文件里（preview / render 会对章，缺章直接报错）。精修时另外把 check.txt 的"文字叠压 / 重影 / 数字先于卡片 / 双重压暗 / 压暗只亮字"都改掉，并用 `frames` 每章至少抽一帧看叠字、拖影、浮空数字、漏画的标注。

**回给主控的消息**不超过 400 字：成片路径和时长；静止段占比；对口型检查结果；在哪些地方断了句；和分镜不一样的地方及原因；还没解决的问题。
之后的画面修改，主控会继续找你。
